# 開発プロセスと生成AIの利用

## 開発体制

本作品は、共同制作者2名が開発責任を持ち、CodexとClaudeを生成AIエージェントとして利用して制作しました。

人間2名が共同で担当した内容は次のとおりです。

- 課題設定と初期案の検討
- AI案の採用、修正、棄却
- AIへの追加指示
- 実行結果と実機動作の確認
- 受入判断とリリース判断
- 展示準備、当日運用、障害監視

生成AIエージェントは、マイルストーン案、コード、テスト、文書の草案作成に使用しました。生成された内容を無条件に採用せず、人間が実行結果と実機動作を確認し、必要に応じて修正または再実装を指示しました。

この文書はコード・テスト・文書作成におけるCodexとClaudeの利用を扱います。Wan2.2 I2Vによる映像と、画像生成支援を使ったUI素材・公開用背景の出典・権利整理は[`../ASSET_LICENSES.md`](../ASSET_LICENSES.md)を参照してください。2026年7月25日の公開用背景のプライバシー編集では、Codexが生成候補を比較し、応募者である共同制作者が採用結果と縮小処理を確認・承認しました。

## 基本的な進め方

1. 人間2名が初期案と解決すべき課題を共同で定める。
2. Codexにマイルストーン案を作成させ、Claudeによる修正と再検討を行う。
3. CodexまたはClaudeへ段階的に実装を依頼する。
4. 人間が処理経過、変更内容、テスト結果、実機動作を確認する。
5. 問題があれば、案を棄却または修正して追加指示を出す。
6. 人間2名が受入、リリース、展示運用を共同で判断する。

## 人間による設計変更の例

QR登録後のスマートフォンと展示機の同期は、当初RESTポーリング中心で実装していました。人間側は画面遷移時に不安定になる可能性を懸念し、実機確認でも不安定な挙動を観測しました。

そこで、人間側からWebSocketによるサーバープッシュ優先方式への変更を提案し、AIエージェントへ再実装を指示しました。REST APIは初期同期と通信障害時のフォールバックとして維持しています。変更後の実機確認と1時間の展示では、同じ問題は観測されませんでした。

技術的な変更記録は[`archive/development-runs/feature-development/20260709-websocket-session-sync.md`](archive/development-runs/feature-development/20260709-websocket-session-sync.md)に残しています。

## アーカイブ内の表現について

過去の記録にある「Claude＝ブレイン」「Codex＝実装」等の表現は、その時点におけるAIエージェント間の作業分担を示す内部運用メモです。プロジェクト全体の課題設定、AI出力の採否、追加指示、受入・リリース判断は、人間2名が共同で担当しました。

過去の生ログは設計判断の履歴として保持し、現在の開発体制を示す文書として書き換えません。現行の担当範囲は[`CONTRIBUTIONS.md`](CONTRIBUTIONS.md)を参照してください。
