# 計測実験計画 — A(チャージ)・B(威力)・AB(スコア) の確定（2026-06-27）

サブエージェント3体（信号メトリクス／スコア設計／実験方法論）の議論を統合した、計算式を実測から決めるための実験計画。実データ `measure-2786samples-4marks.json` を全員が `角速度=motionAmount×50`（intensity フィールドはバグ汚染で不使用）で再分析した上での結論。

## 0. 実データから判明した3つの前提（重要）

1. **真のノイズ床は極めて低い**。汚染前の「rest」は p95≈475 だったが、これは押しっぱなしで腕が動いていたため。本当に静止していた窓だけ抜くと **角速度 median≈3〜5 / p99≈25 / max≈31 deg/s**（motionAmount p99≈0.49 deg/frame）。→ 現 `intensityThresholdBle=150` は過大、`chargeNoiseFloor=0.1` 近辺は妥当。
2. **「中くらい」は人間が意図して作れない**（weak 547 と medium 620〜690 が重なる）。一方 **本気の全力パンチ（peak 1000〜1533 deg/s）は手加減（≤730）から綺麗に分離**。→ 段階ラベル計測は捨て、**完全静止＝下限 / 全力＝上限 / ゆっくり一発＝単調性の最低参照**だけ使う（ユーザ方針と一致）。
3. **パンチは鋭いスパイク（立ち上がり120〜270ms・ピークは1〜3サンプル）、チャージは累積**（本気スイングで約 300〜440 deg/秒 たまる）。検出窓 200〜400ms が妥当（現 `hakkeiWindowMs=400` と整合）。

## 1. 設計決定（何を採るか）

### A: センサ → チャージゲージ
- **主**: `chargeRaw = Σ(回転角 deg, floor超のみ)`（現行）。単調・dt非依存・実装済で堅牢。
- **任意で凸化**: `∫ω²·dt`（速く振るほど非線形に増える）を候補に残す。要 clamp。
- **上限キャップ**: スイング回数 or 時間で飽和させる。
- ゲージ = `clamp01((chargeRaw − chargeMin)/(chargeMax − chargeMin))`。`chargeMax` は「本気で chargeMs 秒振った時の Σ の p95」から逆算（chargeMs とペアで決める。現 2000 は本気3秒≈1300 で満タンにならず要調整）。

### B: パンチ威力
- **主**: 窓内ピーク角速度（**直近2〜3サンプル中央値 / dt≥20ms 限定**でバースト偽ピーク除去）。単調・飽和余裕あり（max1533、quaternion delta レンジに余裕）。
- **副**: 力積 `∫(ω−base)·dt`（strong/weak 分離比 7.2x で最良）。窓を安定化できれば主指標化も可。
- **不採用**: 角加速度・jerk（dtバースト＋50Hz解像度で崩壊）。
- 正規化 = `clamp01((peak − strengthMin)/(strengthMax − strengthMin))`。`strengthMax` = 本気20発の p95（≈1500）。

### AB: スコア合成
- **現行 `power = rightChargeScore × leftChargeScore × hakkeiScore` は廃止**（単手を right/left 両方に入れて実質 `charge²×strength` になる歪み）。
- **推奨式**:
  ```
  gate(B) = clamp((B − Bgate)/(Bfull − Bgate), 0, 1)   // 本気足切り。本気なら常に1.0
  base    = (wA·A + wB·B)/(wA + wB)                     // 0..100 合成本体
  power   = K · gate(B) · base^γ
  ```
  - **A=散らばりの主役（タメ量で Lv0〜5 を決める）、B=空振りゲート＋本気の微ボーナス**。本気プレイでは B はほぼ定数なので、Lv を動かすのは実質 A。
  - 初期値: `wA:wB = 3:1`、`γ = 1.0〜1.5`、`Bgate` は床直上、`Bfull` は本気の下限側。
  - パラメータの役割が直交（A レンジ=Lv散らばり、Bgate=空振り、wB=本気ボーナス、γ=爽快感）。
- **Lv/ランク境界**: 絶対値ハードコードをやめ、**本気プレイの power 分布パーセンタイル**で配置。Lv1/2/3/4/5 ≈ 20/40/60/80p、**Lv5＝上位15〜20%（フルタメのご褒美）**、Lv0＝空振りのみ。S/A/B/C/D も power パーセンタイルで（S は上位10%で希少に）。

## 2. 実験メニュー（全て「本気 or 完全静止」。"中くらい"不要。総所要 約10分）

各セッションは独立した1本の連続録（開始→終了）として保存。ファイル名に内容を入れる。

| # | セッション | 手順 | 反復 | 時間 |
|---|---|---|---|---|
| **S1** | 静止床（ノイズ） | `rest` のまま完全静止。立位／構え／装着直後の3姿勢、各10秒、絶対に動かさない | 3姿勢×10s | ~1分 |
| **S2** | 本気パンチ分布(B) | `strong`→全力前方パンチ1発→2秒完全脱力静止→繰り返し（1発ごとに静止を挟みスパイク分離） | **20発** | ~2分 |
| **S3** | チャージ到達量(A) | `charge`→本気で腕を振り続ける→`rest`静止。「3秒」「6秒」「限界(〜10s)」各数回 | 各3回 | ~2分 |
| **S4** | タメ→本気パンチ(AB) | `charge`→本気スイング数秒→`strong`→本気パンチ1発→`rest`静止。実プレイ1セット相当 | **10セット** | ~3分 |
| **S5** | ゆっくり1発（単調性参照） | `weak`→ゆっくり1発だけ前へ突く→静止。本気の対極＝下限参照のみ | 5発 | ~1分 |

反復根拠: 本気 peak の CV≈20%（1011〜1533）。p5/p50/p95 安定に **20発**（空振り1〜2発除外で18発残る）。チャージは録ごと±20%振れたので各条件3回で中央値。

## 3. 各記録 → 統計量 → 決まる config パラメータ

| セッション | 出す統計量 | 決まるパラメータ |
|---|---|---|
| S1 静止床 | 真静止窓のみで w の p95/p99/max、motionAmount p99 | `punch.intensityThresholdBle`(≈床p99安全側→150から下げ余地)、`normalization.rightChargeNoiseThreshold`、`punch.chargeNoiseFloor`、`hakkei.idleMaxSpeed` |
| S2 本気パンチ | 20発 peak の min/p5/p50/p95/max、立ち上がり | `normalization.hakkeiVelocityMax`(本気p95≈1500)、`hakkeiVelocityMin`、`Bgate/Bfull` |
| S3 チャージ | Σ\|Δdeg\| と /秒レート、chargeMs内累積の p50/p95 | `normalization.rightChargeMax`(chargeMs×レートの p95 で逆算)、`punch.chargeReadyThreshold` |
| S4 タメ→パンチ | (charge累積, peak) ペア分布・相関 | `power.powerCoefficient/yenCoefficient`(K の桁合わせ)、`videoLevels[].minPower`・`rankThresholds`(パーセンタイル逆算) |
| S5 ゆっくり1発 | ゆっくり突きの peak（下限アンカー） | 変換式の下限・`hakkeiVelocityMin` 現実下限、単調性確認 |

単調性チェック: 静止 < ゆっくり一発 < タメ無し本気 < フルタメ本気 で power が単調増加すること。崩れたら wA/wB/γ を再調整。

## 4. 計測UI に要る改善（現 UI が汚染を生んだため、実験前に入れる）

1. **静止床の自動算出ボタン**（最優先）。「床キャプチャ5秒」で5秒だけ録り、その窓の w p95/p99/max・motionAmount p99 をその場表示。rest ラベル運用に頼らず純粋静止だけ取る（「restが動いていた」事故を構造的に防ぐ）。
2. **パンチ自動セグメント**。連続録から「閾値超え→ピーク→減衰」を1イベント自動抽出し peak/rise/間隔をテーブル表示（1発ずつラベル押す手間を排除、S2/S4 が楽に）。
3. **セッションメタ**。エクスポートに `sessionType`(still/punch-burst/charge-hold/charge-punch-set/slow)・姿勢メモ・利き手を含め、ファイル名にも反映。1セッション=1目的を強制。
4. **長区間内の静止/動作 自動分割**表示（動作部だけ統計、静止部は床候補へ）。
5. **live 中央値**（peak の p50/p95、床 p99）でサンプルが十分溜まったかその場判断。
6. **intensity バグ対策**: エクスポートで `intensity` を出さない or `motionAmount×50` の正しい角速度を併記。

## 5. 失敗を避ける注意（実データで観測済み）

- **rest を押しっぱなしで動作デモしない**。床は必ず別セッション S1 で微動だにせず、真静止窓のみから統計。
- **統計は区間平均でなくスパイク検出 peak から**（区間 mean はノイズ込みで実威力より低く出た）。
- **"中くらい"は計測しない**（weak↔medium 不分離）。2点アンカー＋ゆっくり参照で連続マッピング。
- **本気は多めに20発**、明らかな外れ(<500)は除外して18発で分布。
- **dt>40ms のサンプルは積算/peak判定で除外**（稀な欠落・重複）。
- **chargeMax は chargeMs とペアで逆算**（単独で 2000 等と置くと誤設定）。
