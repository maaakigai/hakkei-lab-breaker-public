# M15-10 実機スパイク手順書 — 「利き手1本装着」でmocopiが使えるか潰す

目的: **mocopi 6点ソルバを騙して「利き手の手首1本だけ装着・残り固定」でパンチ強度の近似信号が取れるか**を、コード変更ゼロで15分で判定する。
背景・判定根拠: 開発時のローカルレビュー記録（GO-with-fixes・A1は実機スパイク必須）。

> 重要: これは公式サポートされた1点tracking ではない。**6点全身ソルバの RightHand/LeftHand Transform を「パンチ強度用の近似信号」として流用**する運用。ソルバが許容するかを実機でしか判定できないため、本スパイクで先に潰す。
> 方向は使わない（前/上/下/後ろ識別は廃止確定）。見るのは **magnitude（速さ・加速度・移動量）だけ**。

---

## 0. 判定基準（先に宣言）

### GO（A1' 採用してよい）
- 交代後も sample が途切れない（Hz 維持・座標が動く）。
- **静止で誤発火しない**（10秒じっとで「パンチ強さ達」が出ない）。
- **弱/中/強パンチが数値で分離**（強の `速/加/距` が弱の概ね2倍以上）。
- 1人目/2人目で**閾値を少し調整すれば同じゲーム**になる（mocopi 側の再キャリブ不要）。

### No-Go（A1' 不採用 → 次善へ）
- 手首 Transform が追従しない／値が飛ぶ。
- 交代後に **mocopi PC app 側の再キャリブが必要**になる。
- 強パンチでも値が頭打ちして弱と分離しない（IKクランプが致命的）。
- 固定センサーの置き方で結果が大きく変わる（再現性なし）。

### No-Go 時の次善（Codex 推奨順）
1. **固定4本＋両手2本装着**（solver が両腕入力で安定する可能性。ゲームは利き手1本だけ使う）。
2. **6本装着を簡略化**（バンド/ベスト/手袋/足首具に事前取付→服の上から一括装着。コードリスク0・展示安定性 最高）。
3. 別入力デバイス検討（スマホ/コントローラ/VR tracker）※プロジェクト標準外・別判断。
4. XYN Motion Studio の1/2点対応を事実確認（現状の公式ページでは6/12点のみ）。

---

## 1. 準備（mocopi 初期化 → 固定）
1. **キーボードで動作確認**（mocopi 前のサニティ）: `scripts/windows/run-dev.bat` 起動 → Title→Result が Space/Enter で完走するか。これが通れば app は健全。
2. mocopi PC app 起動 → **通常どおり6本装着してキャリブ**（基本姿勢＋歩行）→ tracking 開始。
3. Unity（`unity-bridge/`・6000.0.77f1・`UnityBridge.unity`）を **Play**。UDP 12351→Unity→45100。
4. mocopi が安定追従しているのを確認したら、**頭・腰・両足のセンサーを外さず、三脚/椅子/台に静止固定**（電源・ペアリングは保持。body 部位割り当てを崩さない）。
5. プレイヤーは**利き手の手首センサー1本だけ装着**。

> ※ mocopi 側の再キャリブは**しない**。Electron 側も方向軸は使わないので、記録パネルに「未実測（default 軸）」警告が出ていても**今回は無視してよい**（magnitude のみ見るため）。

## 2. Electron で受信＆ライブ数値を見る
1. `scripts/windows/run-dev.bat`（または `npm run dev`）→ Title で **Unity Bridge** 選択 → **開始** → **InputCheck**。
2. InputCheck で受信 OK（Hz・座標が動く）を確認。**利き手**は `H` キーで右/左トグル（装着した手に合わせる）。
3. InputCheck 下部の **「記録(M15-09)」パネル**に、突くたびライブで
   **`速`(speedPeak) / `加`(accelPeak) / `距`(netDistance)** と「パンチ強さ達 / 弱（揺れは非発火）」が出る。
   → **これが今回の主計器**。方向(dot値)は無視してよい。

## 3. 計測（条件A' を本命に）
各パンチの直後に画面の `速/加/距` を読む。記録も残す（後で条件比較・閾値用）。

| ラベル（パネルのボタン） | 内容 | 本数 |
|---|---|---|
| `static` | 10秒じっと（手を下げて静止） | 3 |
| `weak-forward` | 弱くだらっと前へ | 10 |
| `forward` | 中くらいの突き | 10 |
| `forward` | 強い一撃（全力） | 10 |

操作: ラベルボタンを押す→その動作を1回→次のラベル or 同じラベルを押し直す（前試行が確定し次が始まる）。崩れた試行は「bad-formで終了」。最後に「この試行を終了(valid)」。
**「JSON書き出し」**で `recording-<timestamp>.json` を保存（条件A'＝固定5本+利き手1本）。

見るポイント（その場で判断できる）:
- **静止3本**：「パンチ強さ達」が一度も出ない → 誤発火0。
- **弱→中→強**：`速/加/距` が単調に増える。強が弱の概ね2倍以上で分離。
- **大きく腕を出した時** `距`(netDistance) が頭打ちしないか（IKクランプの兆候）。

## 4. 交代テスト（運用の肝）
1. **利き手センサーだけ2人目へ付け替え**（mocopi 側は触らない・再キャリブしない）。
2. InputCheck に戻り、sample が途切れず座標が動くか確認。
3. 同じ `static×3 / weak×10 / forward中×10 / forward強×10` を録る → 別 JSON で保存（条件A'・player2）。
4. 1人目と2人目で**閾値を少しずらせば同じ遊びになるか**を `速/加/距` の分布で見る。

## 5.（任意）条件比較
時間が許せば同じ計測を **B=固定4本+両手2本 / C=通常6本装着** でも録ると、A' がダメな場合の判断材料になる。
オフライン比較は記録JSONを見れば足りる（今回は方向 sweep は不要。`速/加/距` の分離と静止誤発火だけ見る）。

## 6. 結果の戻し方
- スパイク後、**GO / No-Go（＋採った条件 A'/B/C）と所見**を Claude に共有（agmsg 経由 or 口頭）。
- GO なら: SPEC §0.24（1-hand magnitude-only）権威化＋ソフト簡素化（方向/hidden/idle/DominantHandCheck 撤去・Calibration を quality/baseline/gain へ縮小）に着手。
- No-Go なら: 次善（4+2 → 6本簡略化）へ。ソフト簡素化自体はどの条件でも共通で進められる。
