# 損害見積書用 備品・設備候補リスト

対象は，展示会場の研究室を題材にした「発勁ラボブレイカー」の Result 見積書表示である．

この文書はコード変更ではなく，見積書に出す備品名，設備名，単価感，Lv別の壊れ方を決めるための企画メモである．

## 方針

- 厳密な資産台帳ではなく，ゲーム用の「それ壊したらあかんやつやん」と思える見積書を作る．
- 写真に写っているものは優先する．ただし，対象研究室に実際にあるものは写真で見えていなくても候補に入れる．
- 実在製品名や実在ブランド名は使ってよい．ただし，写真から型番が読めないものは「命名案」として扱う．
- 単価は新品再購入費，復旧作業費，撤去清掃費を含むゲーム用概算でよい．
- 同じLv帯では結果が大きく逸脱しないよう，低めの乱数を想定する．
- 人物，顔，個人名，PC画面内容，読める書類，私物の所有者推定は扱わない．

## 確度

| 確度 | 意味 |
|---|---|
| confirmed | 写真または既存背景で確認できる |
| lab-known | 対象研究室にある，または研究室用途としてユーザーが許容した |
| named | 写真では汎用品に見えるが，Result用に具体名を命名した |
| joke | ゲーム演出用の小ネタ枠 |

## Result表示のトーン

見積書の文体は硬めにする．ただし，品名に少しだけ内輪感を入れて，研究室を知る人が笑える余地を残す．

例:

```text
被害見積書

Toshiba液晶モニター交換費　　　　　2台　¥86,000
Anker USB-C ハブ交換費　　　　　　1台　¥8,800
ケーブル沼復旧作業費　　　　　　　1式　¥42,000
Dell 27インチ 4Kモニター交換費　　1台　¥64,000

合計損害額
¥200,800
```

## 決定事項（2026-07-07 実装済み）

実装は `src/renderer/damageEstimate.ts`（純ロジック）＋ `resultPresenter.ts`（表示）＋ `config/score.config.json`（`power.damageAnchors` / `resultDamageReport`）。

- **単価**: 範囲（`unitPriceMin`〜`unitPriceMax`）から seed で低乱数選択。100円単位に丸め。同じ結果は毎回同じ見積書（決定的）。
- **行数**: `maxLinesByLevel = [3,3,4,6,8,10]`（Lv0..5・末尾の調整行を含む）。
- **損害総額**: `power.damageAnchors` の区分線形補間（非線形）＋`damageVarianceRatio=0.07`（±7%・seed量子化）。ランク/Lvはアンカー金額に内包。旧「Power×係数」は廃止（yenCoefficient は後方互換で残置・未使用）。
  - アンカー（**2026-07-07 サブエージェント4体の現実性検証で「忠実版」に確定**）: `0→0 / 40k→0 / 50k→¥5万 / 150k→¥50万 / 300k→¥200万 / 600k→¥700万 / 780k→¥3,000万`。
  - 検算: Lv1≈¥0（無被害）/ Lv2≈¥27.5万 / Lv3≈¥125万 / Lv4≈¥450万 / Lv5≈¥1,850万 / Lv5上端¥3,000万。**億は付けない＝Critical（企業ビル）に委譲**。
  - 検証結論: 対象研究室の「1部屋」の全損は中身の再購入＋原状回復で ¥1,500〜3,000万が現実的（資産査定/原状回復/大学調達/現場研究者の4視点一致）。A案の Lv5=¥1.2億・Lv4=¥4,000万は**過大**として棄却。
  - 品目の「研究室スラブ・壁構造復旧費（¥数千万）」は**削除**（動画のLv5は室内全損で建物躯体は崩落せず＝構造費目は過大/二重計上）。代わりに「内装・天井・床 原状回復（全面）¥300〜900万」を追加。
- **見積書の作り方**: 総額を最低Lvを満たす品目へ按分（単価×数量）。高単価品を優先配置＋top-upで既存行に寄せ、末尾「調整行（粉塵清掃／Lv4以上は原状回復工事）」で端数を吸収し **Σ＝総額** を厳密一致。
- **Critical**: 同じ見積書体裁。企業ビル行（各 `bonusDamageYen`）＋「研究室設備 全損 一式（＝研究室側の総額）」で **Σ＝合計損害額**。
- **消費税/端数行**: 出さない（合計のみ）。
- **私物（バッグ類）**: 出さない（プライバシー方針どおり）。

### 残（任意調整）
- Lv帯上端（Lv4≈550k / Lv5≈760k）は総額が品目ceilingを超え、調整行（原状回復工事）が 40〜55% になる（全壊の復旧費として妥当だが、より品目化したければ Lv4向け高単価品の追加や maxCount 引き上げで調整可）。
- 単価・品目・weight・アンカー金額はすべて scripts/windows/Settings.bat / `config/score.config.json` で可変。
